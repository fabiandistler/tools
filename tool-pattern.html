🛠️ Werkzeuge, die aus einer einzigen Datei bestehen

Diese Seite zeigt zehn wiederkehrende Bausteine für kleine Web-Werkzeuge — genau die Art, aus der auch alle anderen Tools in dieser Sammlung gebaut sind. Jeder Baustein hat eine Demo zum Anfassen; der Code steht darunter und ist zugeklappt, bis du ihn sehen willst.

Was ist überhaupt gemeint?

Eine Internetseite besteht normalerweise aus vielen Teilen, die ein Server zusammensetzt und ausliefert. Ein Werkzeug aus einer Datei bricht damit: Alles steckt in einer einzigen Datei, die auf .html endet. Text, Aussehen und Verhalten liegen darin nebeneinander.

Diese Datei kann man per E-Mail verschicken, auf den Schreibtisch legen und doppelklicken. Sie öffnet sich im Browser und funktioniert — ohne Installation, ohne Konto, ohne dass irgendwo im Hintergrund ein Rechner mitlaufen muss.

Browser — das Programm, mit dem du gerade liest: Safari, Chrome, Firefox. Es kann viel mehr, als Seiten anzeigen: rechnen, zeichnen, Dateien lesen, Daten abholen. Genau das nutzen diese Werkzeuge aus.

Vier Regeln, die alles zusammenhalten

  • Eine Datei. Aussehen und Verhalten stecken mit im selben Dokument, nicht in Nachbardateien. Was du hast, ist das ganze Werkzeug.
  • Kein Zusammenbau nötig. Die Datei wird nicht vorher durch ein Programm geschickt, das aus ihr etwas Lauffähiges macht. Sie ist schon lauffähig.
  • Fremder Code nur, wenn er wirklich nötig ist — und dann direkt aus dem Netz nachgeladen, nicht mitinstalliert.
  • Klein bleiben. Ein paar hundert Zeilen. Kurz genug, dass man sie ganz liest — und dass eine KI sie am Stück umschreiben kann.
Zusammenbau (auf Englisch build step) — bei größeren Web-Projekten schreibt man Code in einer bequemeren Form, den der Browser gar nicht versteht. Ein Hilfsprogramm übersetzt ihn vorher. Das ist mächtig, kostet aber Werkzeugkette, Wartezeit und Fehlerquellen. Für kleine Werkzeuge lohnt es sich nicht.

Warum das gerade jetzt interessant ist

Eine KI kann ein solches Werkzeug in einem Rutsch schreiben, weil das Ergebnis ein einziger Textblock ist: kopieren, als .html speichern, öffnen, fertig. Passt etwas nicht, beschreibt man die Änderung und bekommt die ganze Datei neu. Bei einem Projekt aus dreißig Dateien mit Zusammenbau funktioniert das nicht annähernd so gut.

Die Sammlung der Bausteine geht auf einen Artikel von Simon Willison zurück: Useful patterns for building HTML tools (englisch). Diese Seite ist selbst eine einzige .html-Datei und damit ihr eigenes Beispiel.

Das Grundvokabular

Browser
Das Programm, in dem du Internetseiten ansiehst — Safari, Chrome, Firefox, Edge.
HTML
Die Sprache, in der der Inhalt einer Seite beschrieben wird: Überschrift, Absatz, Knopf, Eingabefeld. Reiner Text mit spitzen Klammern drumherum.
CSS
Die Sprache für das Aussehen: Farben, Abstände, Schriftgrößen. Legt fest, wie das aussieht, was HTML benennt.
JavaScript
Die Sprache für das Verhalten: Was passiert, wenn jemand tippt oder klickt. Jeder Browser kann sie ausführen, ohne dass etwas installiert werden muss.
Server
Ein Rechner, der irgendwo dauerhaft läuft und auf Anfragen antwortet. Die Werkzeuge hier brauchen keinen — sie rechnen auf deinem Gerät.
Auf dem Gerät / lokal
„Passiert bei dir, nicht bei jemand anderem." Nichts wird verschickt, nichts landet auf einem fremden Rechner.

Wörter, die in den Bausteinen vorkommen

Zwischenablage
Der unsichtbare Zwischenspeicher beim Kopieren und Einfügen. Enthält oft mehrere Fassungen desselben Inhalts gleichzeitig — etwa Text mit und ohne Formatierung.
Webadresse (URL)
Das, was oben in der Adresszeile steht. Alles ab dem Rautezeichen # nennt man den Anker. Der Teil wird nie an einen Server geschickt — deshalb eignet er sich, um Einstellungen in einem teilbaren Link unterzubringen.
Browser-Speicher (localStorage)
Ein kleines Notizfach, das jede Internetseite in deinem Browser bekommt. Was dort liegt, bleibt nach dem Schließen erhalten, gilt aber nur für diesen einen Browser auf diesem einen Gerät — und geht niemanden sonst etwas an.
Datenquelle / Schnittstelle (API)
Eine Internetadresse, die keine Seite zum Ansehen zurückgibt, sondern rohe Daten zum Weiterverarbeiten. „Wie ein Automat: Frage rein, Datenpaket raus."
JSON
Das übliche Format solcher Datenpakete. Sieht aus wie eine verschachtelte Liste mit Doppelpunkten und geschweiften Klammern, ist aber schlicht Text und für Menschen lesbar.
CORS
Die Erlaubnis einer fremden Datenquelle, direkt aus einer Seite heraus abgefragt zu werden. Ohne sie blockiert der Browser die Anfrage — als Schutz, damit nicht jede Seite in deinem Namen überall nachfragen kann. „Steht die Erlaubnis nicht dran, geht es nicht — und das ist kein Fehler, sondern Absicht."
Bibliothek
Fertiger Code von anderen Leuten für eine wiederkehrende Aufgabe, etwa Diagramme zeichnen oder Tabellen einlesen. Man bindet ihn ein, statt es selbst zu schreiben.
CDN
Ein öffentliches Lager für solche Bibliotheken, aus dem der Browser sie beim Öffnen der Seite direkt nachlädt. Eine Zeile in der Datei genügt, es wird nichts installiert.
Zusammenbau (build step)
Ein Zwischenschritt, bei dem ein Hilfsprogramm den geschriebenen Code erst in eine Form übersetzt, die der Browser versteht. Für große Projekte üblich, für kleine Werkzeuge überflüssiger Ballast.
React
Ein sehr verbreitetes Baukastensystem für große Web-Oberflächen. Es setzt einen Zusammenbau voraus — und fällt für Werkzeuge aus einer Datei deshalb weg.
Zugangsschlüssel (API-Schlüssel)
Eine lange Zeichenkette, mit der sich ein Programm bei einem Dienst ausweist — wie ein Passwort, nur für Maschinen. Gehört nie in den Code der Datei, sondern in den Browser-Speicher.
KI-Sprachmodell (LLM)
Ein Dienst wie Claude, ChatGPT oder Gemini. Man schickt Text hin und bekommt Text zurück — technisch gesehen eine ganz normale Datenquelle mit Zugangsschlüssel.
GitHub Pages
Ein kostenloser Ort, an dem eine .html-Datei unter einer echten Internetadresse liegen kann. Datei hochladen, Link teilen. So ist auch diese Seite erreichbar.

🧬 Baustein 1 — Der Aufbau einer Datei

Jedes dieser Werkzeuge hat dasselbe Grundgerüst. Wer es einmal gesehen hat, erkennt es in jeder Datei wieder — und weiß, wo man etwas ändert.

Drei Bereiche, immer in derselben Reihenfolge

  1. Der Kopf. Titel der Seite und das Aussehen (alle Farben, Abstände, Schriftgrößen an einer Stelle).
  2. Der sichtbare Teil. Was man auf dem Bildschirm sieht: Überschriften, Eingabefelder, Knöpfe, Ausgabebereiche.
  3. Das Verhalten. Ganz unten der Teil, der auf Klicks und Eingaben reagiert und die Ausgaben füllt.

Mehr ist es nicht. Alles Weitere auf dieser Seite sind Ergänzungen an genau diesen drei Stellen.

Warum kein Zusammenbau, warum kein React?

Sobald ein Projekt einen Zusammenbau braucht, ist die geschriebene Datei nicht mehr das, was am Ende läuft. Man kann sie nicht mehr einfach doppelklicken, nicht mehr per Mail schicken, und eine KI kann ihr Ergebnis nicht mehr direkt einsetzbar ausgeben.

Für kleine Werkzeuge ist der Preis zu hoch. Deshalb die Faustregel: Wenn du eine KI um so ein Werkzeug bittest, schreib „ohne React, alles in einer HTML-Datei" dazu. Dieser Halbsatz erspart die gesamte Werkzeugkette.

React — ein Baukasten für große Web-Oberflächen, in der Branche sehr verbreitet. Für zehn Eingabefelder und einen Knopf ist er das falsche Werkzeug, und er zieht den Zusammenbau zwingend nach sich.

Warum eine einzige Datei so viel wert ist

  • Aus der Antwort einer KI direkt speicherbar — kein Verteilen auf Ordner.
  • In Sekunden veröffentlicht, etwa über GitHub Pages.
  • Eine KI kann das ganze Werkzeug am Stück neu schreiben, weil sie es am Stück lesen kann.
  • Nichts kann fehlen. Die Datei ist vollständig, für immer.
Das Grundgerüst als Code ansehen 
<!-- Eine einzige .html-Datei — mehr braucht es nicht -->
<!DOCTYPE html>
<html lang="de">
<head>
  <meta charset="UTF-8">
  <!-- diese Zeile sorgt dafür, dass es auf dem Handy passt -->
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>Mein Werkzeug</title>

  <style>
    /* 1. Das Aussehen — alles an einer Stelle */
    :root { --akzent: #6c8eff; }
  </style>
</head>
<body>
  <!-- 2. Der sichtbare Teil: Eingabe → Knopf → Ausgabe -->

  <script>
    // 3. Das Verhalten. Reines JavaScript, kein React, kein Zusammenbau.
    // Fehler werden in der Seite angezeigt, nie als Warnfenster.
  </script>
</body>
</html>

📋 Baustein 2 — Kopieren und Einfügen

Der schnellste Weg, etwas in ein Werkzeug hinein- und wieder herauszubekommen, ist die Zwischenablage. Kein Hochladen, kein Speichern, kein Dateiname — einfach einfügen, und am Ende ein Knopf, der das Ergebnis wieder mitnimmt.

Was viele nicht wissen

Beim Kopieren landet fast nie nur eine Sache in der Zwischenablage, sondern mehrere Fassungen gleichzeitig. Kopierst du etwas aus einem Textprogramm, liegt dort der reine Text und die formatierte Fassung und manchmal ein Bild. Das Werkzeug darf sich aussuchen, welche es nimmt.

Format — die Angabe, um welche Art Inhalt es sich handelt. text/plain heißt reiner Text, text/html formatierter Text, image/png ein Bild. Die Demo unten zeigt dir, was gerade in deiner Zwischenablage liegt.

🔗 Baustein 3 — Eingaben in der Adresse merken

Alles, was jemand eingestellt hat, wandert hinten in die Webadresse. Die Seite lässt sich dann als Lesezeichen ablegen oder verschicken — und wer den Link öffnet, sieht genau denselben Stand. Ganz ohne Konto und ohne Server.

Der Trick mit dem Rautezeichen

Alles in einer Webadresse ab dem # heißt Anker und wird beim Aufrufen nicht mitgeschickt — dieser Teil bleibt im Browser. Genau deshalb kann man Einstellungen dort ablegen: Sie stehen im Link, sind aber nie über die Leitung gegangen.

Nur für Harmloses. Was in einem Link steht, steht auch im Verlauf, im Lesezeichen und in jeder Chatnachricht, in die er kopiert wird. Zugangsschlüssel gehören dorthin nicht — für die gibt es Baustein 4.

function syncToURL() {
  const stand = {
    name:  document.getElementById('name').value,
    farbe: document.getElementById('farbe').value,

}

💾 Baustein 4 — Merken im Browser

Jede Internetseite bekommt in deinem Browser ein eigenes kleines Notizfach. Was dort liegt, überlebt das Schließen des Tabs und den Neustart des Rechners — verlässt aber niemals das Gerät.

Was man darüber wissen sollte

  • Es gehört zur Seite, nicht zu dir. Ein anderer Browser oder ein privates Fenster sieht ein leeres Fach.
  • Es geht nirgendwo hin. Kein Server bekommt etwas davon mit — deshalb ist es der richtige Ort für Zugangsschlüssel.
  • Es kann verschwinden. Wer die Browserdaten löscht, löscht es mit. Für Wichtiges also zusätzlich als Datei sichern, siehe Baustein 6.
Zugangsschlüssel — eine lange Zeichenkette, mit der sich ein Programm bei einem Dienst ausweist; ein Passwort für Maschinen. Er darf nie im Code der Datei stehen, denn den kann jeder lesen, der die Seite öffnet. Stattdessen fragt das Werkzeug einmal danach und legt ihn ins Notizfach.

// Speichern, aber erst 800 ms nach dem letzten Tastendruck —
// sonst würde bei jedem Buchstaben geschrieben.
let timer;
feld.addEventListener('input', () => {
  clearTimeout(timer);
  timer = setTimeout(() => {
    localStorage.setItem('entwurf', feld.value);
  }, 800);
});

// Beim Öffnen zurückholen
feld.value = localStorage.getItem('entwurf') || '';

// Zugangsschlüssel: einmal fragen, dann merken
let schluessel = localStorage.getItem('schluessel');
if (!schluessel) {
  schluessel = prompt('Bitte Zugangsschlüssel eingeben:');
  if (schluessel) localStorage.setItem('schluessel', schluessel);
}

📂 Baustein 5 — Dateien öffnen, ohne sie herzugeben

Eine Datei in die Seite ziehen und sofort verarbeiten: Der Browser darf sie lesen, ohne dass sie irgendwohin hochgeladen wird. Sie bleibt auf deinem Gerät — bei Tabellen, Verträgen oder Fotos ist das der entscheidende Unterschied.

Was damit geht

  • Eine Tabelle einlesen, auswerten und das Ergebnis anzeigen.
  • Ein Foto anschauen, verkleinern, drehen — ohne dass es je einen fremden Rechner sieht.
  • Text aus einem gescannten Dokument herausholen (dafür braucht es dann Baustein 9).

Der Browser lässt dabei nur das zu, was du selbst ausgewählt oder hineingezogen hast. Von sich aus kommt eine Seite an keine einzige Datei deines Geräts.

⬇️ Baustein 6 — Dateien erzeugen

Umgekehrt geht es genauso: Das Werkzeug baut eine Datei zusammen und legt sie in deinen Download-Ordner. Tabelle, Bild, Termin für den Kalender — alles im Browser gebaut, kein Server beteiligt.

Wie das funktioniert

Der Browser bekommt einen Textblock und die Angabe, was für eine Art Datei das sein soll. Daraus erzeugt er einen unsichtbaren Link und klickt ihn selbst an — was für dich aussieht wie ein ganz normaler Download.

Dateiart (technisch MIME-Typ) — die Angabe text/csv oder image/svg+xml. Daran erkennt das Betriebssystem, mit welchem Programm es die Datei öffnen soll. Derselbe Text wird so einmal zur Tabelle und einmal zum Bild.

Demo: vier Dateiarten erzeugen

Inhalte anpassen und einen der Knöpfe drücken — die Datei landet in den Downloads.
Wie das im Code aussieht 
// Ein Helfer für alle Dateiarten
function downloadFile(inhalt, dateiname, art) {
  const paket   = new Blob([inhalt], { type: art });
  const adresse = URL.createObjectURL(paket);
  const link = document.createElement('a');
  link.href = adresse;
  link.download = dateiname;
  link.click();                 // unsichtbar anklicken
  URL.revokeObjectURL(adresse); // Speicher wieder freigeben
}

downloadFile(tabelle, 'export.csv', 'text/csv');
downloadFile(bild,    'symbol.svg', 'image/svg+xml');
downloadFile(termin,  'termin.ics', 'text/calendar');

🌐 Baustein 7 — Daten aus dem Netz holen

Manche Dienste geben ihre Daten roh heraus, damit andere Programme damit arbeiten können. Ein Werkzeug aus einer Datei kann sie direkt abfragen und braucht dafür wieder keinen eigenen Server.

Warum das nicht bei jeder Adresse klappt

Der Browser lässt eine Seite nicht einfach bei beliebigen fremden Adressen anfragen. Sonst könnte jede beliebige Seite in deinem Namen bei deiner Bank nachsehen, solange du dort angemeldet bist.

Deshalb muss die Gegenseite die Erlaubnis ausdrücklich mitschicken. Diese Erlaubnis heißt CORS. Fehlt sie, blockiert der Browser — das ist kein Fehler im Werkzeug, sondern Absicht. Die zweite Demo unten prüft für eine beliebige Adresse, ob die Erlaubnis da ist.

🤖 Baustein 8 — Eine KI mitbenutzen

Ein KI-Sprachmodell ist von außen betrachtet nichts Besonderes: eine Datenquelle wie in Baustein 7, nur dass man Text hinschickt und Text zurückbekommt. Damit kann ein Werkzeug aus einer Datei zusammenfassen, übersetzen oder sortieren.

Was du dafür brauchst — und was das kostet

Einen Zugangsschlüssel des Anbieters. Der wird nach Verbrauch abgerechnet: pro Anfrage meist Bruchteile eines Cents, aber eben nicht null. Ein Konto bei Anthropic, OpenAI oder Google reicht; der Schlüssel wird dort einmal erzeugt.

Der Schlüssel landet nur im Notizfach deines Browsers (Baustein 4), nie im Code. Wer die Datei weitergibt, gibt seinen Schlüssel nicht mit — die andere Person hinterlegt einfach ihren eigenen.

Vorsicht bei geteilten Geräten. Was im Browser-Speicher liegt, kann jedes Programm auslesen, das in diesem Browser läuft. Für einen privaten Rechner in Ordnung, für ein öffentliches Gerät nicht.

// Anfrage an Claude — der Schlüssel kommt aus dem Browser-Speicher
async function frageClaude(text, schluessel) {
  const antwort = await fetch('https://api.anthropic.com/v1/messages', {
    method: 'POST',
    headers: {
      'x-api-key': schluessel,
      'anthropic-version': '2023-06-01',
      'content-type': 'application/json',
      // nötig, damit die Anfrage direkt aus dem Browser erlaubt ist
      'anthropic-dangerous-direct-browser-access': 'true'
    },
    body: JSON.stringify({
      model: 'claude-haiku-4-5-20251001',
      max_tokens: 1024,
      messages: [{ role: 'user', content: text }]
    })
  });
  const daten = await antwort.json();
  return daten.content[0].text;
}

📦 Baustein 9 — Fremden Code einbinden

Manches schreibt man nicht selbst: Diagramme zeichnen, PDFs lesen, Text aus Bildern holen. Dafür gibt es fertige Bausteine anderer Leute. Eine Zeile in der Datei genügt — der Browser lädt sie beim Öffnen nach, installiert wird nichts.

Zwei Regeln

  • Nur, wenn es wirklich nötig ist. Jede eingebundene Bibliothek ist etwas, das kaputtgehen kann. Vieles geht ohne.
  • Immer mit fester Versionsnummer. Steht in der Adresse 9.1.6, bekommst du in zwei Jahren noch genau dasselbe. Ohne Nummer ändert sich das Werkzeug irgendwann von allein — und niemand weiß, warum.
CDN — ein öffentliches Lager für solche Bibliotheken, weltweit gespiegelt, damit das Nachladen schnell geht. Bekannte sind cdnjs und jsDelivr. Man lädt dort nichts hoch, man verlinkt nur.

PDFs lesen und anzeigen — PDF.js
Text aus Bildern holen — Tesseract.js
Tabellen einlesen — Papa Parse
Diagramme zeichnen — Chart.js
Code farbig hervorheben — highlight.js
QR-Codes erzeugen — qrcode.js
Python im Browser ausführen — Pyodide

🔍 Baustein 10 — Erst nachsehen, dann bauen

Der nützlichste Baustein ist der unscheinbarste: ein winziges Werkzeug, das nur anzeigt, was eigentlich vorhanden ist. Wer einmal gesehen hat, was beim Einfügen alles mitkommt, hat plötzlich Ideen für zehn weitere Werkzeuge.

Das Vorgehen

  1. Ein Werkzeug bauen, das nur nachsieht und nichts verändert.
  2. Anschauen, welche Angaben tatsächlich zur Verfügung stehen.
  3. Erst danach das eigentliche Werkzeug bauen — jetzt mit dem Wissen, was möglich ist.

Genau so ist die Zwischenablage-Demo aus Baustein 2 entstanden. Sie ist nichts als ein Fenster auf etwas, das man sonst nie zu sehen bekommt.

Der Zwischenablage-Betrachter, komplett 
document.addEventListener('paste', async e => {
  e.preventDefault();
  console.log('Teile:', e.clipboardData.items.length);
  console.log('Dateien:', e.clipboardData.files.length);

  for (const teil of e.clipboardData.items) {
    console.log('Format:', teil.type, 'Art:', teil.kind);
    if (teil.kind === 'string') {
      teil.getAsString(s => console.log(s.substring(0, 200)));
    }
    if (teil.kind === 'file') {
      const f = teil.getAsFile();
      console.log('Datei:', f.name, f.size, f.type);
    }
  }
});
